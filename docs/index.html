01One command, ranked findings

Point it at a URL and it runs the three web detectors. Add --repo and it pats down the codebase too. Worst things first, fixes included.

02The five detectors

◆ Headers

Missing HSTS, CSP, X-Content-Type-Options, X-Frame-Options, Referrer-Policy, Permissions-Policy — plus unsafe-inline and insecure cookies.

◆ TLS

Certificate expiry (expired or under 21 days), invalid chains, untrusted CAs, hostname mismatches.

◆ Stack / EOL

Fingerprints the CMS, framework and server, then checks endoflife.date so "Drupal 9" comes with a deadline attached.

◆ Secrets

AWS keys, private-key blocks, API tokens, JWTs and IBAN/PII patterns in the repo, reported with file:line. Respects .gitignore.

◆ Deps / CVE

Known CVEs in package-lock.json and composer.lock via the OSV.dev API.

◆ CI-ready

--fail-on critical exits non-zero when it matters. --json pipes the whole report anywhere.

03Usage

Each flag answers one question.

CommandAnswers
frisk https://example.comIs this site's front door locked? (Headers, TLS, Stack)
frisk … --repo ./code…and what's leaking inside? (+ Secrets, Deps)
frisk … --jsonCan I pipe this into something else?
frisk … --fail-on criticalShould this deploy be blocked?

04Why it exists

The decisions worth knowing about, written down.

Passive means safe

frisk never attacks anything. It reads what any browser would see, plus the repo you point it at. Safe to run against a prospect before the first call.

Fast enough to actually run

Five detectors in parallel, one binary, results in seconds. A check that takes minutes is a check that gets skipped.

Findings come with fixes

Every finding prints the remediation, not just the problem. Copy, paste, done — that's what makes it a pre-flight instead of a lecture.
